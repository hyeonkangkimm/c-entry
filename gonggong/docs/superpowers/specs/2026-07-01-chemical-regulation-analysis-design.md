# 화학물질 규제 및 처벌 가능성 분석 설계

## 목표

상품 페이지에서 추출한 성분명을 한국환경공단 화학물질 정보 조회 API로 조회하여 규제 가능성을 판정하고, 확장 프로그램의 `행정처분 및 형사처벌` 카드에 확인 가능한 근거만 표시한다.

## 입력과 범위

- 분석 입력은 `RiskDashboardAnalyzeRequest.normalizedIngredients()`이다.
- HSK 코드와 리콜 결과는 대시보드 문맥으로 유지하지만 화학물질 API 검색어로 사용하지 않는다.
- 환경공단 API에서 물질명, CAS번호, 물질분류 유형·고유번호, 함량·예외·고시 정보를 파싱한다.
- 환경공단 API는 법적 처벌을 직접 확정하지 않으므로 처벌 정보는 별도 규칙표에서만 가져온다.

## API 연동

- 외부 연동은 `ChemicalInformationClient` 인터페이스와 HTTP 구현체로 분리한다.
- API URL, 서비스 키, 동시 호출 수, 개별 타임아웃은 설정값으로 관리한다.
- 기본 동시 호출 수는 4, 개별 호출 타임아웃은 3초다.
- 중복 제거된 성분별 요청을 제한된 실행기에서 비동기로 수행한 후 결과를 입력 순서대로 합친다.
- 한 성분의 실패가 다른 성분 조회를 취소하지 않는다.
- 서비스 키와 원문 응답 전체를 로그에 남기지 않는다.

## 법령 규칙표

- YAML 규칙표는 API의 물질분류 고유번호를 키로 사용한다.
- 각 규칙은 분류명, 규제 여부, 의무 법령·조문·근거 URL, 처벌 조문·문구·근거 URL, 시행 시작일·종료일을 가진다.
- 현재 날짜에 유효한 규칙만 사용한다.
- 함량, 용도, 수입량 또는 예외 조건을 현재 요청 정보로 확정할 수 없으면 처벌을 단정하지 않고 `적용 가능` 정보만 표시한다.
- 국가법령정보센터에서 공식 근거를 확인하지 못한 처벌 조항은 규칙표에 넣지 않고 응답에서도 생략한다.
- 처벌 규칙 작성이 신뢰성 있게 완료되지 않으면 처벌 필드를 비운 채 성분·CAS번호·분류·관련 법률만 제공한다.

## 판정

- 규제 규칙과 매칭된 성분이 하나라도 있으면 `DANGER`다.
- 모든 성분을 정상 조회했고 규제 성분이 없으면 `SAFE`다.
- 일부 성분만 조회 또는 매칭에 실패하고 규제 성분이 없으면 `WARNING`이다.
- 입력 성분이 없거나 모든 성분이 외국어·특이 표기 등으로 미매칭이면 `UNKNOWN`이다.
- 외부 API 전체 장애, 인증 실패 또는 타임아웃이면 `UNAVAILABLE`이다.
- 규제 성분이 검출된 상태에서 다른 성분이 실패해도 `DANGER`를 유지하고 미분석 성분 경고를 함께 반환한다.

## 응답

- `ChemicalRiskResponse`는 상태, 점수, 메시지, 규제 성분 목록, 미분석 성분 목록, 분석 불가 여부, 직접 검색 URL, 버튼 문구를 제공한다.
- 규제 성분 항목은 성분명, CAS번호, 유해성/물질분류, 관련 법률, 적용 가능 처벌 조항과 각 근거 URL을 제공한다.
- 빈 처벌 정보는 JSON에서 `null`로 제공하며 UI에서 영역 자체를 숨긴다.
- 직접 검색 기본 URL은 `https://icis.mcee.go.kr/chmClsCl/chmClsCIView.do?hlhsn_sn=4823`이다.
- 버튼 기본 문구는 `화학 물질 종합정보시스템에서 직접 성분 검색하기`다.

## 확장 프로그램 UI

- `risk-view.js`에 독립적인 화학물질 카드 렌더러를 추가한다.
- `DANGER` 카드에는 규제 성분명, CAS번호, 분류, 관련 법률과 확인된 적용 가능 처벌 조항을 목록으로 표시한다.
- `WARNING`, `UNKNOWN`, `UNAVAILABLE` 카드에는 `[시스템 성분 분석 불가능 품목]` 마킹과 직접 검색 버튼을 표시한다.
- 일부 실패가 포함된 `DANGER` 카드에도 미분석 마킹과 직접 검색 버튼을 추가한다.
- 외부 링크는 HTTP(S)만 허용하고 새 탭에서 `noopener noreferrer`로 연다.

## 오류 처리

- API 응답의 필수 식별 필드가 없으면 해당 성분을 미매칭으로 처리한다.
- JSON/XML 중 설정된 응답 형식을 엄격히 파싱하고 예상하지 못한 스키마는 가용성 오류로 기록한다.
- 개별 성분 오류와 전체 시스템 오류를 구분해 상태를 계산한다.
- 사용자에게 법률 판단을 확정하는 표현을 사용하지 않고 수입 전 확인이 필요한 위험 신호임을 명시한다.

## 테스트

- API 요청 파라미터, URL 인코딩, 타임아웃과 응답 파싱을 HTTP 전송 계층 없이 단위 테스트한다.
- 최대 동시 실행 수와 개별 실패 격리를 검증한다.
- 규제·비규제·부분 실패·전체 실패·입력 없음 상태 판정을 검증한다.
- 시행일과 근거 URL이 있는 규칙만 처벌 정보로 노출되는지 검증한다.
- 공식 처벌 근거가 없으면 처벌 필드가 비어 있는지 검증한다.
- UI에서 분석 불가 마킹, 직접 검색 버튼, 규제 성분 목록, 안전한 URL 처리와 정상 상태 버튼 미표시를 검증한다.
